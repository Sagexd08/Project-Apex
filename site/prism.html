Abstract

What this is, in one paragraph.

Agentic workloads read and write the same vector store within milliseconds of each other, and published measurements show tail latency inflating when inserts run during queries. We describe Prism, a storage layout for that case. Each vector is rotated by a seeded randomized Hadamard transform and stored once as four nested bit planes, so the quantizer has no trained state and cannot drift as the data changes. A query runs an error-gated cascade: it scores every vector with one bit and reads further planes only for candidates that can still reach the top k. Readers search immutable snapshots pinned to a write-ahead-log position, so a reader never waits for a writer and never sees a partial write.

In a Rust reference implementation on synthetic data (20,000 vectors, 256 dimensions, 1,000 queries), a gate width of z = 3 returned the same top 10 as exact search for all 1,000 queries while reading about 1.06 bits per coordinate per vector, against 4 for a flat 4-bit scan; at z = 2 recall@10 was 0.998. This gate is a calibrated heuristic, so the match is an observation, not a guarantee; the only certified bound we tested reads 3.7 to 4.0 bits. Bits read is not total memory, because raw float32 vectors must be kept for the exact rerank. The saving in bits read was not shown to become a saving in time: with a lookup-table kernel the z = 2 cascade took 0.61 ms per query against 0.55 ms for an optimised exact float scan in the first run, and 0.48 ms against 0.63 ms in a re-run on a busy machine. The time comparison is inconclusive: the sign reversed between runs. On harder synthetic sets it read 1.3 to 1.4 bits at z = 2, and over seven alternating trials a concurrent writer raised median P99 latency by 21% (range 12% to 34%). Open problems: a gate whose provable width does not cost most of the saving, real embedding data, and a kernel that beats an optimised exact scan.

Memory fast enough to disappear.

A statement of direction. Anything not measured in the evidence section is a belief, and we say so. The research behind it: the abstract, the film of the mathematics, the paper and the evidence.

  • Agents write while they read.

    Most storage was built to load in bulk, index, then query for a long time. An agent loop reads, acts and writes within milliseconds. Storage that makes writes wait for reads, or the reverse, becomes the slowest step in the loop.

  • Nothing to train means nothing to drift.

    A compressor learned from yesterday’s data is wrong about tomorrow’s. A fixed random rotation has no opinion about the data, so it cannot go out of date, and a new vector can be encoded the moment it arrives.

  • Pay for precision only when the question needs it.

    Most of a corpus is plainly irrelevant to a given query, and one bit is enough to say so. Spend more bits only on the few vectors still in the running.

  • A reader never waits for a writer, and never sees half a write.

    Every read happens against a named position in the log. The same question at the same position gives the same answer, so a surprising result can be replayed and explained.

  • Say what was measured.

    Every number carries its data, its machine and a checksum of the code that produced it. A number from synthetic data says so. A claim without a measurement is a goal, and we label it as one.

  • Keep it open.

    The reference implementation, the benchmark and the raw results are public, so anyone can disagree with us with evidence.

North star

Proposed goal, not a claim: an open-source vector database that agents can use as memory, built by one person with agents.

We want model labs and model hubs to choose it because it is better, not because it is ours. That is a goal. We have no customers and we claim none. What we can do is write down the bar they would apply, and clear it in public:

  • Speed on public data. Recall against latency curves versus the leading engines, on SIFT1M, GIST1M and a current text-embedding set, on identical hardware.
  • Honest concurrency. P99 under agent-rate writes, over hours, on a quiet machine.
  • Durability. Power-loss tests and an independent review before anyone is asked to trust it with memory.
  • Isolation. Tenant boundaries proved by tests that try to break them.
  • Drop-in for agents. An embedded Rust library, SDKs and an MCP server, so an agent can use it without glue.
  • Reproducible. Every number from a public script, with a checksum, that a stranger can re-run.

What it is for

A person running an agent on their own machine, with their own data, who should not need a cluster to give that agent a memory. A small team that wants retrieval it can reason about and replay. A research community that deserves an open reference for the read-while-writing case, not only the static one.

What would make us wrong

If bytes saved do not become time saved on real hardware. If real embeddings are far less friendly than our synthetic clusters. If the gate misses neighbours more often than its tuning suggests. If an existing system already gives the same result. We will publish the outcome either way.

Algorithm

The mathematics, end to end.

Full derivations, with assumptions, are in docs/prism/MATH_AND_ALGORITHM.md. The essentials:

Angle from bits

θ̂ = π · H / d
std(θ̂) = π · √( p(1−p) / d ),  p = θ/π
std(cos θ̂) ≈ sin θ · std(θ̂)

A random hyperplane separates two unit vectors with probability θ/π. The Hamming distance H over d bits estimates the angle.

Rotation makes data look alike

z = (H·D₃)(H·D₂)(H·D₁) x / P^{3/2}
coordinate ≈ N(0, 1/d)
cost O(P log P), state = a seed

Three rounds of random signs and a fast Walsh-Hadamard transform stand in for a Haar rotation. The assumption is tested, not proved.

Nested quantizer

Δ_b = 2C / (√P · 2^b)
idx_b = idx_4 >> (4 − b)
σ_b ≈ C / (√(3P) · 2^b)

One stored 4-bit code gives every lower precision. Each extra bit halves the score error, and the error does not depend on the data.

The gate

keep c  iff  ŝ(c) + zσ ≥ τ − zσ
provable: z ≥ √(2 ln(2(k+1)S/δ))
k=10, S=3, δ=0.01  →  z ≈ 4.2

The lemma is conditional on bounded errors. The provable width costs most of the saving, which is the main open problem.

Cost

B = n·m₁ + n₁·m₂ + n₂·m₃   (bits)
n_j ≈ k + n·g(t)·2zσ_j
floor: B ≥ n bits per query

Survivors beyond k shrink in proportion to σ. Prism speeds up a scan; it does not remove it.

Snapshots

V(ε, ℓ) = { r : lsn(r) ≤ ℓ }
I1 repeatable   I2 no torn read
I3 monotonic    I4 compaction-safe

Segments are immutable. A commit publishes a new snapshot pointer; a reader clones the pointer and never locks again.

ENCODE(x): z = rotate(x, seed) idx = clamp(floor((z + s) / Δ₄), 0, 15) store 4 bit planes + full vector (for rerank) SEARCH(q, k, schedule, z, snapshot): rq = rotate(q, seed); cand = all vectors in snapshot for each b in schedule: est = score(rq, cand, planes up to b) τ = k-th largest of est cand = { c : est[c] + zσ_b ≥ τ − zσ_b } return top-k of cand by exact cosine

Paper

The research paper.

Condensed here. The full text is docs/prism/PAPER.md.

1 /Introduction

An agent reads, acts, writes and reads again within milliseconds. A query over n vectors is mostly a question of how many bytes cross memory, and the store changes while it is queried. Other work reports P99 latency rising roughly 280% to 345% under concurrent inserts (arXiv 2606.08950) and data-dependent quantizers degrading or needing rebuilds under updates (arXiv 2512.18335). We have not reproduced these.

Prism rests on three observations: a random rotation makes any unit vector look the same, so the quantizer needs no training; a uniform quantizer’s codes nest, so bit planes serve every precision; and one bit is enough to reject most of a corpus.

2 /Related work

Random hyperplane signs estimate angles (Goemans and Williamson; Charikar). Randomized Hadamard transforms give fast rotations (Ailon and Chazelle). TurboQuant rotates, quantizes per coordinate and adds a 1-bit residual transform for unbiased inner products. RaBitQ gives a 1-bit code with a theoretical error bound that supports reliable reranking. Multi-stage filtering is a standard idea.

Our claim is narrower: nested planes, a multi-stage gate and log-pinned snapshots, evaluated for read-while-write. A fuller related-work pass could shrink it. We read abstracts and summaries, so every citation needs checking against the primary text.

3 /Design

Rotate with three rounds of random signs and a Walsh-Hadamard transform. Clip at C/√P, quantize each coordinate to 16 levels, and store the four index bits as four planes; plane one is the sign bit. Keep full-precision vectors for the final rerank on a slower tier.

Search scores everything at one bit, keeps candidates whose score plus zσ can still reach the k-th best minus zσ, reads the next plane for the survivors, and reranks the last few exactly. Writers seal immutable segments and publish a new snapshot; readers clone the pointer and never lock again.

4 /Analysis

Score error has variance about Δ²/12, so σ_b ≈ C/(√(3P)·2^b): each extra bit halves it, and the data does not enter. If every true top-k item and one witness have error within zσ, no top-k item is dropped. A union bound needs z near 4.2 for a 1% failure budget at k = 10 over three stages, so the z = 2 to 3 gate used in the experiments is a heuristic; only the deterministic residual-norm bound is certified. Storage: 4-bit planes add 1/8 to the retained float32 vectors, so total memory is about 1.125x float32, not 1/8. Bits read are n·m₁ + n₁·m₂ + n₂·m₃, with a floor of n bits per query, so Prism accelerates a scan and does not remove it.

5 /Evaluation

20,000 vectors, d = 256, 50 Gaussian clusters, 1,000 queries from the same mixture, k = 10. At z = 3 the cascade returned the same top 10 as exact search for every query (an observation, not a guarantee) while reading 1.06 bits per coordinate against 4 for a flat 4-bit scan. At z = 2 recall@10 was 0.998 with 1.7% of queries missing a neighbour. Measured σ matched the formula within 13% at one bit and within 3% at four. Reconstruction error was within about 3% on shifted data. On harder synthetic sets (out-of-distribution queries, isotropic data, overlapping clusters, 100,000 vectors) it read 1.04 to 1.40 bits at z = 2 with recall at least 0.997. The tables are in the evidence section.

6 /What cuts against us

The cascade has not been shown to be faster than an exact float scan. With a lookup-table kernel the z = 2 cascade took 0.61 ms per query against 0.55 ms for an optimised exact scan at 20,000 vectors in the first run, and 0.48 ms against 0.63 ms in a re-run on a busy machine. The sign reversed, so the time comparison is inconclusive. Bits read were not shown to become time.

The error tails are heavier than a bell curve: over 20 million pairs the largest error was 5.2 to 7.1 standard deviations, so a gate that never misses needs z near 7. A per-vector bound costs about as many bits as z = 4, and a deterministic bound prunes almost nothing.

A concurrent writer raised median P99 by 21% over seven alternating trials, and reader throughput fell 12%. Readers do not lock, so the cost is shared CPU and memory, which we have not profiled. Out-of-distribution queries read 1.40 bits, not the 1.77 of an early prototype, so our explanation for that gap was wrong and the gap is unexplained.

7 /Next

A SIMD kernel and timing at larger n, where memory bandwidth matters. A sharper per-vector bound in the style of RaBitQ. Real embedding sets. A quiet-machine concurrent benchmark with a multi-core writer and profiling. A partitioning index in front, deletes, filtered search and a PrismIndex for the Atlas AnnIndex trait. Baselines on identical hardware: flat float, product quantization, RaBitQ and a TurboQuant-style scheme.

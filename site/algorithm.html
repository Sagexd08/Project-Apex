Algorithm

One stored code, read progressively: encode once, score with a few bits, spend more only where the answer is still in doubt.

The idea in four steps

  1. Rotate. Apply a fixed, seeded randomized Hadamard rotation so every vector looks statistically alike. No codebook, nothing to train.
  2. Encode once. Quantize each rotated coordinate to a 4-bit cell and store the four bits as four nested planes. The first plane is the sign bit.
  3. Cascade. Score every vector with plane 1 only. Drop the ones that clearly cannot reach the top k. Add the next plane for the survivors, and repeat.
  4. Rerank exactly. Fetch the full-precision vectors of the final few survivors and rank them with the true score, ties by ascending id.

Encoding

A stored vector can have any shape: a few large coordinates, or many small ones. Scalar quantizers handle the second shape well and the first badly. A random rotation removes the difference, which is why no training is needed. A dense rotation costs O(d²) per vector, so Prism uses three rounds of a seeded random sign flip followed by a fast Walsh–Hadamard transform, O(P log P), where P is the next power of two at or above d.

ENCODE(x, seed): # writer, per vector z = rotate(x, seed) idx = clamp(floor((z + s_c) / Δ_4), 0, 15) plane p (p = 0..3) = bit p of every idx, packed into u64 words return (planes, x) # x is kept for the exact rerank

The b-bit index is the top b bits of the 4-bit index, so one stored copy serves 1, 2, 3 or 4 bit scoring. A query reads only the planes it needs.

The cascade

SEARCH(q, k, schedule=[b_1..b_S], z, snapshot): rq = rotate(q, seed) cand = all vectors visible in the snapshot for j in 1..S: est = { c : ŝ_{b_j}(rq, c) } # read planes up to b_j τ = k-th largest of est cand = { c : est[c] + zσ_j ≥ τ − zσ_j } return top-k of cand by exact ⟨q, x⟩, ties by ascending id

The gate keeps a candidate if it could still be within the error margin of the k-th best. Setting z is the whole story: a small z prunes hard and may drop a true neighbour, a large z is safe and prunes little.

Two different gates

The global zσ gate above is heuristic: it is calibrated, and its miss rate is measured, not guaranteed. The only gate with a guarantee uses each vector's stored residual norm (Cauchy–Schwarz). In our experiment that gate never missed, and it pruned almost nothing at d = 256. Closing that gap is the main open problem; see the mathematics.

Complete storage accounting

Four-bit planes are not an eightfold memory saving. Exact reranking needs the original float32 vector, so it is stored too. Prism reduces the bytes read per query, not the bytes stored.

Snapshots in one paragraph

Segments are immutable once sealed. A commit builds one new sealed segment and publishes a new snapshot that lists the old segments plus the new one. A reader copies the current snapshot pointer, then never takes a lock again. Because the quantizer has no trained state, a writer encodes a new vector from the seed alone: no codebook to retrain and no moment when stored codes and the quantizer disagree. The full definition, and what is not yet defined, is on the snapshot protocol page.

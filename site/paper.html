Prism: nested bit planes, an error-gated cascade and log-pinned snapshots for vector memory that is read while it is written

Bat DB

No authors or affiliations are claimed beyond the project

Abstract

Agentic workloads read and write the same vector store within milliseconds of each other, and other work reports tail latency inflating when inserts run during queries (reported, not reproduced here). We propose Prism, a storage layout for that case. Each vector is rotated by a seeded randomized Hadamard transform and stored once as four nested bit planes, so the quantizer has no trained state and cannot drift as the data changes. A query runs an error-gated cascade: it scores every vector with one bit and reads further planes only for candidates that can still reach the top k. Readers search immutable snapshots pinned to a write-ahead-log position, so a reader takes no lock after pinning and does not see a partial write (implemented and tested for one writer and four readers). In a Rust reference implementation on synthetic data (20,000 vectors, 256 dimensions, 1,000 queries), a gate width of z = 3 returned the same top 10 as exact search for all 1,000 queries while reading about 1.06 bits per coordinate per vector, against 4 for a flat 4-bit scan; at z = 2 recall@10 was 0.998. This gate is a calibrated heuristic, so the match is an observation, not a guarantee; the only certified bound we tested reads 3.7 to 4.0 bits. Bits read is not total memory, because raw float32 vectors must be kept for the exact rerank. The saving in bits read was not shown to become a saving in time: with a lookup-table kernel the z = 2 cascade took 0.61 ms per query against 0.55 ms for an optimised exact float scan in the first run, and 0.48 ms against 0.63 ms in a re-run on a busy machine. The time comparison is inconclusive: the sign reversed between runs. On harder synthetic sets it read 1.3 to 1.4 bits at z = 2, and over seven alternating trials a concurrent writer raised median P99 latency by 21% (range 12% to 34%). Open problems: a gate whose provable width does not cost most of the saving, real embedding data, and a kernel that beats an optimised exact scan.

1. Introduction

An agent reads what it knows, acts, writes what it learned and reads again, often within milliseconds. Vector storage for this loop faces two pressures. A query over n vectors is mostly a question of how many bytes are pulled through memory. And the store changes while it is being queried, so any structure that must be rebuilt or retrained when data changes either goes stale or makes someone wait.

Other work reports the second pressure is real (Reported, not reproduced). A study of vector databases under concurrent inserts reports P99 latency rising by roughly 280% to 345%, attributed to brute-force scans of unindexed segments and to lock contention (arXiv 2606.08950). A vendor benchmark reports P99 inflation between 1.1x and 10.3x across six engines under streaming load (OceanBase, 2026). A separate paper notes that data-dependent quantizers degrade or require rebuilds under insertions and deletions (arXiv 2512.18335). We have not independently reproduced any of these.

We propose Prism (Proposed; the observations below are Proved or Measured as marked in sections 4 and 6), built on three observations:

  1. A random rotation makes any unit vector look statistically the same, so a quantizer applied after rotation needs no training and cannot drift.
  2. A uniform quantizer's codes are nested: the top b bits of a 4-bit code are a valid b-bit code. Storing the code as bit planes lets one copy serve every precision.
  3. Most of a corpus can be rejected at one bit. A gate based on the score error decides which candidates deserve more bits.

A fourth element, snapshots keyed to the write-ahead-log position, addresses concurrency.

2. Related work

Random hyperplane signs estimate angles (Goemans and Williamson, 1995; Charikar, 2002), which is the basis for 1-bit codes. Randomized Hadamard transforms give fast approximate rotations (Ailon and Chazelle, 2006). TurboQuant (ICLR 2026) rotates vectors, quantizes each coordinate, and adds a 1-bit residual transform for unbiased inner products, with distortion within about 2.7x of a lower bound as the authors report. RaBitQ (SIGMOD 2024) gives a 1-bit-per-dimension code with a theoretical error bound that supports reliable reranking, and a 2025 extension covers moderate compression rates. Multi-stage filtering with progressively more precise distance estimates is a standard idea in similarity search.

What we propose is narrower than any of these, and we do not claim priority: the combination of nested bit planes, a gate over several stages, and snapshots tied to the log, evaluated for read-while-write. A fuller related-work pass could reduce the claim further. We read abstracts and summaries of the cited papers, not all of the full texts; the citations must be checked against the primary sources before submission.

References to verify: Goemans and Williamson, J. ACM 42(6), 1995. Charikar, STOC 2002. Ailon and Chazelle, STOC 2006. Gao and Long, RaBitQ, SIGMOD 2024 (arXiv 2405.12497). Zandieh et al., TurboQuant, ICLR 2026 (arXiv 2504.19874).

3. Design

Rotation. Pad to P, the next power of two, and apply three rounds of a seeded random sign diagonal followed by a Walsh-Hadamard transform scaled by 1/sqrt(P). Cost O(P log P) per vector; the only state is the seed.

Planes. Clip at C/sqrt(P) with C = 3, quantize each coordinate uniformly to 16 levels, and store the four index bits as four separate packed planes. Plane 0 is the sign bit. Full-precision float32 vectors must be retained for the final exact rerank; they can live on a slower tier, but they are not removed. See the storage accounting in section 4.

Cascade. At stage j with b_j bits, estimate every candidate's score, take the k-th best estimate tau_j, and keep candidates with s_hat + z*sigma_j >= tau_j - z*sigma_j. sigma_j is the measured standard deviation of the estimate error. After the last stage, rerank survivors exactly.

Snapshots. Segments are immutable. A commit seals a new segment and publishes a new snapshot (a list of segments and a log position). A reader clones the snapshot pointer and then takes no further locks. Invariants: repeatability, no torn reads, monotonic pins, and compaction that never changes the visible set.

4. Analysis

Error per bit. For fine cells, the score error has variance about Delta_b^2 / 12, giving sigma_b ~ C / (sqrt(3P) * 2^b). Each added bit halves it. The error does not depend on the data.

Gate safety. If every true top-k item and one witness item have error within z*sigma, no top-k item is dropped (lemma, proof in MATH_AND_ALGORITHM.md section 4). A union bound over k+1 items and S stages gives a failure probability of at most (k+1)*S*Pr[|error| > z*sigma]. For a sub-Gaussian error and a 1% failure budget with k = 10, S = 3, this requires z near 4.2 (Proved under the sub-Gaussian assumption; the measured tails are heavier, section 6.6). The z gate used in section 6 is therefore a heuristic.

Cost (bits read). Bits read are B = n*m_1 + n_1*m_2 + n_2*m_3, with a floor of n bits per query. Prism is a scan accelerator and does not remove the scan.

Storage accounting (total memory). Bits read per query is not memory. Per vector of dimension d, Prism stores 4 bits per coordinate of planes (4d bits, or 1/8 of float32) plus the retained float32 vector (32d bits) plus a residual norm, so total storage is about 1.125x float32 plus metadata, not 1/8. The 4-bit planes alone are 1/8 of float32, but the recall figures in section 6 depend on an exact rerank, which reads the float32 vectors. The saving is in bytes read per query (Measured), and the float32 tier can sit on slower storage (Proposed, not measured). Any "8x" claim applies to the code only.

5. Implementation

A zero-dependency Rust crate, benchmarks/prism, about 700 lines of source: rotation, quantizer, store with snapshots, search, a deterministic generator, a benchmark binary and seven tests (Implemented and Tested as reported by the benchmark run; not re-run in this wording pass): norm preservation, nesting, sigma within 20% of the formula, exact result at very large z, compaction transparency, a 2-second one-writer four-reader invariant test, and cascade recall at z = 3). The scoring loop is scalar, with no lookup tables or SIMD.

6.3 Why stage 1 is so effective here, and a warning

Stage 1 keeps about 399 vectors for every z from 2 to 4. The generator makes 50 clusters of about 400 vectors, and the query comes from one of them. The 1-bit stage isolates that cluster, and the later stages only choose among its members. This is the easy case.

Our first prototype (numpy) drew the queries from a separate set of cluster centres and read about 1.77 bits per coordinate at z = 2. We guessed that the query distribution explained the difference. Section 6.6 tests that guess: out-of-distribution queries on the Rust code read 1.40 bits, not 1.77, so the guess was incomplete and the remaining gap is unexplained. The practical point is that the saving depends on how much structure the data and queries have, and real embeddings may land anywhere in this range.

Gates. Error shape is close to Gaussian (excess kurtosis between -0.02 and 0.23) but the tails are heavier: over 20 million pairs per set the largest error was 5.2 to 7.1 standard deviations, so a gate with zero misses over every pair would need z near 7.1. A certified guarantee therefore costs most of the saving on hard data; this is the main unresolved result. Only the deterministic bound is certified; the global z gate and the per-vector probabilistic bound are heuristics.

Concurrency. Seven alternating writer-off and writer-on trials of 3 seconds with four lookup-table readers and a writer committing about 1,900 vectors per second. The median ratio of P99 latency, concurrent over serial, was 1.21 (range 1.12 to 1.34), and every trial was above 1. Median reader throughput fell from 6,007 to 5,255 queries per second (-12%). The earlier ratio of 0.56 was noise. Readers take no lock after pinning, so the cost is shared CPU and memory bandwidth, which we have not profiled. Snapshots remove blocking, not contention.

7. Limitations

All data is synthetic. The gate width is calibrated, and the provable alternatives cost most of the saving on hard data (6.6). The scan floor is one bit per vector. Whether the lookup-table cascade is faster than an optimised exact scan at 20,000 vectors is inconclusive (the sign reversed between two runs), and larger n and SIMD are untested. A concurrent writer raises median P99 by about 21% and cuts reader throughput by about 12%. There are no deletes, no filtered search and no integration with the Atlas AnnIndex trait. There is no comparison with RaBitQ, product quantization, HNSW or any database. Timing is from one non-idle machine whose CPU model was not recorded.

8. Future work

  1. A SIMD kernel, and timing at larger n where memory bandwidth dominates.
  2. A sharper per-vector bound in the style of RaBitQ, to close the gap between the empirical z near 2 and a provable width.
  3. Real embedding sets (for example SIFT1M, GIST1M and a recent text-embedding set).
  4. A quiet-machine concurrent benchmark with a multi-core writer and profiling of the cost of contention.
  5. A partitioning index in front of the cascade, to go below the one-bit floor, and filtered search.
  6. Baselines on identical hardware: flat float, product quantization, RaBitQ, TurboQuant-style, HNSW.
  7. Deletes in the snapshot model, and a PrismIndex implementing AnnIndex fed from the WAL.

Appendix A

Mathematics and algorithm

Prism: mathematics and algorithm, end to end

Status: Research Note v1.0 (preprint, not peer reviewed). Statuses used: Proved (under the stated assumptions), Measured (in results.json), Proposed. The global zσ gate in section 4 is a heuristic; only the deterministic residual-norm bound is certified. Storage: float32 vectors are retained for the exact rerank, so 4-bit planes add 1/8 to float32 and do not make total memory 1/8. Derivations are first-order and state their assumptions. Notation: d is the vector dimension, P the next power of two at or above d, n the corpus size, k the result size, q a query and x a stored vector, both unit length. s(q,x) = <q,x> is cosine similarity.

1. Geometry: why bits can rank neighbours

For unit vectors, <q,x> = cos θ, so ranking by inner product is ranking by angle.

Take a random hyperplane through the origin with unit normal g. The sign bits sign<g,q> and sign<g,x> differ exactly when the hyperplane separates the two vectors, which happens with probability

Pr[ sign<g,q> != sign<g,x> ] = θ / π            (Goemans and Williamson)

With d independent hyperplanes, the Hamming distance H between the two bit strings is Binomial(d, θ/π). That gives an angle estimator and its spread:

θ̂ = π · H / d
E[θ̂] = θ
std(θ̂) = π · sqrt( p (1 - p) / d ),      p = θ / π
std(cos θ̂) ≈ sin θ · std(θ̂)
true anglestd of θ̂ at d = 256std of cos θ̂

Reading: a 1-bit code is sharpest for near neighbours (small sin θ) and blurriest for unrelated vectors. Nearest-neighbour search only needs to be sharp where the answer is, so the cheapest code is already most precise where it matters. The error shrinks as 1/sqrt(d); that is a property of dimension, not of tuning.

2. Rotation: making every vector look the same

A stored vector can have any shape: a few large coordinates, or many small ones. A scalar quantizer does badly on the first shape and well on the second. A random rotation removes the difference.

If R is a Haar-random orthogonal matrix and x is a unit vector, each coordinate of Rx has density proportional to (1 - t²)^((d-3)/2), mean 0 and variance 1/d. For large d this is close to N(0, 1/d), and coordinates are nearly independent. The distribution of Rx does not depend on x. This is the reason the quantizer needs no training: the data is made to look the same before it is quantized.

A dense R costs O(d²) per vector and d² floats to store. Prism uses a randomized Hadamard rotation instead:

rotate(x):
    z = zero_pad(x, P)
    repeat 3 times:
        z = z ⊙ D_r              # D_r: seeded random ±1 diagonal
        z = FWHT(z) / sqrt(P)    # fast Walsh-Hadamard transform, O(P log P)
    return z

Each round is orthogonal, so ‖z‖ is preserved. Three rounds are a standard approximation of a Haar rotation. The only state is the seed. The approximation is an assumption of the analysis below, and the test suite checks norm preservation and the measured error against the formula.

3. Quantizer: nested bit planes

Let s_c = C / sqrt(P) with clip constant C = 3 (three standard deviations of a coordinate). For a rotated coordinate z, the 4-bit index and its levels are:

Δ_4   = 2 s_c / 16
idx_4 = clamp( floor( (z + s_c) / Δ_4 ), 0, 15 )

The b-bit index is the top b bits of idx_4:

idx_b = idx_4 >> (4 - b),      Δ_b = 2 s_c / 2^b
recon_b(idx) = (idx + 0.5) · Δ_b - s_c

Nesting holds because Δ_b = 2^(4-b) Δ_4 and clipping is applied to the same interval, so floor((z + s_c) / Δ_b) = floor(idx_4 / 2^(4-b)). Plane 0, the most significant bit, is [z ≥ 0]: it is the SimHash bit of section 1. Each extra plane halves the cell width.

Storage layout: four planes, each P bits per vector, packed in u64 words. One stored copy therefore serves 1, 2, 3 or 4 bit scoring, and a query reads only the planes it needs.

Error of the estimated score

The estimate at b bits is ŝ_b = <Rq, recon_b(Rx)>, and the error is

ε_b = ŝ_b - s = Σ_i (Rq)_i · e_i,      e_i = recon_b(z_i) - z_i

For fine cells, e_i is close to uniform on [-Δ_b/2, Δ_b/2] with variance Δ_b² / 12, and Σ (Rq)_i² = 1. So

Var(ε_b) ≈ Δ_b² / 12 = C² / (3 P · 4^b)
σ_b ≈ C / ( sqrt(3 P) · 2^b )

For P = 256, C = 3: σ_1 ≈ 0.054, σ_2 ≈ 0.027, σ_4 ≈ 0.0068. A first numpy prototype measured 0.0576, 0.0272, 0.0069. The coarse 1-bit case sits above the formula because the uniform-error assumption is weakest there and clipping adds error.

Consequences:

  • Each added plane halves the error. Four planes cut it by 16.
  • The error does not depend on the data, only on P, C and b. This is the formal version of "nothing to train, nothing to drift".
  • This is an MSE quantizer, so ŝ_b is slightly biased toward zero. A residual sign bit (the QJL step in TurboQuant) makes it unbiased. Prism v0 does not include it.

4. The gate: when it is safe to drop a candidate

Let t be the true k-th best score, and τ_j the k-th best estimate among current candidates at stage j. The gate keeps a candidate c if

ŝ_j(c) + z σ_j  ≥  τ_j - z σ_j

Lemma (gate safety; Proved, conditional on the stated assumption). Suppose, at stage j, every true top-k item c and one witness item w satisfy |ε_j| ≤ z σ_j. Then no true top-k item is dropped.

Proof. At least k candidates have estimate ≥ τ_j. Fewer than k items have true score > t, so at least one of those k candidates, call it w, has s(w) ≤ t. Then τ_j ≤ ŝ_j(w) ≤ s(w) + zσ_j ≤ t + zσ_j. For a true top-k item c, ŝ_j(c) ≥ s(c) - zσ_j ≥ t - zσ_j ≥ τ_j - 2zσ_j, which is the gate condition. ∎

The lemma is conditional. To make it unconditional, bound the probability that the assumption fails. Over S stages and k + 1 items, a union bound gives

Pr[ any true top-k item is dropped ]  ≤  (k + 1) · S · Pr[ |ε| > z σ ]

If the error is sub-Gaussian with variance proxy σ², Pr[|ε| > zσ] ≤ 2 exp(-z²/2), so a failure budget δ needs

z  ≥  sqrt( 2 ln( 2 (k + 1) S / δ ) )

For k = 10, S = 3, δ = 0.01: z ≈ 4.2. A Hoeffding bound on a bounded uniform error has variance proxy Δ²/4, three times the true variance, which pushes the provable z higher still. In the experiments the useful range is z ≈ 2 to 3.

Open problem. The provable z (above 4) costs most of the saving that an empirical z of 2 gives. Closing that gap, with per-vector bounds of the kind RaBitQ derives, is the main research question. Until it is closed, the correct statement is: the gate is empirically calibrated and its miss rate is measured, not guaranteed.

Measured tails. Over 20 million (query, vector) pairs per set, the score error was close to Gaussian in shape (excess kurtosis -0.02 to 0.23) with maximum |error|/sigma of 5.2 to 7.1, so zero misses over every pair needs z near 7.1. A per-vector bound using the stored residual norm r_x, |s_hat - s| <= r_x * sqrt(2 ln(2/delta) / d), held on at least 99.94% of pairs at delta = 0.001 but read about as many bits as z = 4. The deterministic bound |s_hat - s| <= r_x (Cauchy-Schwarz) never missed and pruned almost nothing at d = 256, because it ignores that the error direction is random relative to the query. See PAPER.md section 6.6.

5. Cost model: bytes touched

Stage 1 reads b_1 bits for all n vectors. Stage j > 1 reads the new planes for the n_{j-1} survivors. Define m_j = b_j - b_{j-1} with b_0 = 0:

B = n · m_1 + n_1 · m_2 + n_2 · m_3          bits per query, incremental planes
B_prefix = n · b_1 + n_1 · b_2 + n_2 · b_3   if each stage re-reads its whole prefix

The experiments report both. A rerank fetches n_S full-precision vectors.

Survivor count, first order. A candidate survives stage j if its estimate is within about 2zσ_j of the threshold, so

n_j  ≈  k  +  n · g(t) · 2 z σ_j

where g(t) is the density of the similarity distribution at the threshold (per unit similarity, per vector). The excess over k is proportional to σ_j, so each extra bit halves it. The approximation needs the window 2zσ_j to be small compared to the scale on which g changes. At 1 bit the window is wide and the formula overestimates; the measured survivor counts are in the paper.

Floor. With one bit per vector read in stage 1, B ≥ n bits. Prism accelerates a scan. It does not remove the scan. Going below n bits per query needs a partitioning index (cluster or graph) in front of it, which is future work and is where the ANN spike in docs/ANN_SPIKE.md is relevant.

What is stored. Prism does not reduce stored bytes: it keeps the planes (P/2 bytes per vector at 4 bits) and full-precision vectors for the rerank. It reduces bytes read per query. The full-precision vectors can sit on a slower tier because only n_S of them are fetched per query.

6. Tail latency

Per-query cost varies with how many vectors sit near that query's threshold, n · g(t_q). Queries in dense regions have more survivors. The experiments report the mean and the 95th percentile of bits read and of reranks, because the tail depends on the spread of g(t_q) across queries, not on the mean.

For reads against writes, the design aim is that a reader's cost is independent of the writer's activity, which would make the concurrent P99 equal the serial P99 apart from memory-bandwidth sharing. The experiment measures the ratio concurrent P99 over serial P99 as a jitter ratio.

7. Snapshots

Definitions. The log assigns each commit a sequence number ℓ ∈ ℕ. A snapshot pin p = (ε, ℓ) names an epoch ε = (seed, d, schedule) and a position ℓ. The visible set is

V(p) = { r : lsn(r) ≤ ℓ }        (deletes are future work: add  and  del_lsn(r) > ℓ )

Invariants.

  • I1 Repeatability. For a fixed pin and query, the result is identical every time, regardless of concurrent commits.
  • I2 No torn reads. A commit is visible whole (all planes and the full-precision vector) or not at all.
  • I3 Monotonicity. Successive pins by one reader have non-decreasing ℓ.
  • I4 Compaction transparency. Compaction changes layout, never V.

Mechanism. Segments are immutable once sealed. The store holds a pointer to the current snapshot, a list of segment pointers plus its ℓ. A commit builds one new sealed segment and swaps in a new snapshot that lists the old segments plus the new one. A reader clones the current pointer (a read lock held for a pointer copy) and then never takes a lock again. I1 and I2 follow because a snapshot never changes after publication, and I3 follows because the pointer only moves forward. I4 holds because compaction replaces several segments with one holding the same records.

Because the quantizer has no trained state, a writer encodes a new vector from the seed alone. There is no codebook to retrain, no global rebuild, and no moment when stored codes and the quantizer disagree.

Cost: many tiny segments make a scan visit many small blocks. Compaction merges them, and the benchmark reports throughput with and without compaction.

8. Algorithms

ENCODE(x, seed):                          # writer, per vector, O(P log P)
    z   = rotate(x, seed)
    idx = clamp(floor((z + s_c) / Δ_4), 0, 15)
    for plane p in 0..4: bit p of every coordinate -> packed words
    return (planes, x)                     # x kept for rerank

COMMIT(batch):                             # single writer
    seg  = seal(ENCODE(v) for v in batch)
    lock writer mutex
        snap' = Snapshot{ lsn = cur.lsn + 1, segments = cur.segments + [seg] }
        publish snap'                      # pointer swap under a short write lock
    return snap'.lsn

SEARCH(q, k, schedule=[b_1..b_S], z, snap):
    rq    = rotate(q, seed)
    cand  = all vectors in snap
    for j in 1..S:
        est = { c : ŝ_{b_j}(rq, c) }       # read planes up to b_j
        τ   = k-th largest of est
        cand = { c : est[c] + z σ_j ≥ τ - z σ_j }
    return top-k of cand by exact <q, x>, ties by ascending id

CALIBRATE(sample of (q, x) pairs):
    σ_b = std( ŝ_b(q, x) - <q, x> )  for b in schedule

SEARCH scores each survivor from planes it already holds plus new planes; the reference implementation counts bits both ways. CALIBRATE runs once per epoch.

Certified interval cascade

Prism: certified interval cascade (Stage C, 2026-10-27)

Status: Research Note v1.0, not peer reviewed. Statuses: Proved (derivation here, real arithmetic), Proposed (not proved or not tested), Derived, first order (heuristic estimate). Nothing here has been run; Stage D reproduces only the existing synthetic pilot.

Notation as in MATH_AND_ALGORITHM.md: R orthogonal rotation, x' = Rx, q' = Rq, P padded dimension, s(q,x) = <q,x> = <q',x'>.

C.1 Valid intervals from the stored code

At b bits each coordinate x'_i falls in a cell. For an interior cell, [l_i, u_i] = [idx*D_b - s_c, idx*D_b - s_c + D_b] with D_b = 2 s_c / 2^b. The two end cells absorb clipped coordinates, so they are not bounded by s_c. Because ||x'|| = ||x|| = 1, every coordinate satisfies |x'_i| <= 1, so the end cells are [-1, -s_c + D_b] and [s_c - D_b, 1]. These are valid and wide.

Box bounds (Proved). With m_i = min(q'_i l_i, q'_i u_i) and M_i = max(q'_i l_i, q'_i u_i):

L_box(x) = sum_i m_i  <=  <q',x'>  <=  sum_i M_i = U_box(x)

Each term satisfies m_i <= q'_i x'_i <= M_i, and summing preserves the inequality.

Norm bound (Proved). Let x_hat be the reconstruction and r = ||x' - x_hat||, stored per vector. Then |<q',x'> - <q',x_hat>| <= ||q'|| r = r by Cauchy-Schwarz.

Intersection (Proved). Both hold, so L = max(L_box, s_hat - r) and U = min(U_box, s_hat + r) are valid. The intersection is never worse than either alone.

C.2 Discard rule and exactness

Let E be the eligible set: vectors visible in the reader's snapshot, passing the filter, belonging to the caller's tenant. Let tau be the k-th largest L(c) over c in E (no pruning if |E| < k).

Rule. Discard c in E iff U(c) < tau (strict).

Lemma 1 (safe under any tie policy; Proved). A discarded c is not in the top-k of E, however ties are broken.

Proof. At least k candidates c' have L(c') >= tau; c is not among them, since L(c) <= U(c) < tau. For each, s(c') >= L(c') >= tau > U(c) >= s(c). So at least k members of E score strictly above c. Hence c ranks below k regardless of how equal scores are ordered. QED

Theorem 2 (exactness; Proved, real arithmetic). If every interval is valid, ranking the survivors by their exact score, ties by ascending id, gives the same list as ranking all of E that way.

Proof. By Lemma 1 no member of the true top-k is discarded; the survivors are a superset of it. The exact top-k of a superset that contains the exact top-k, under the same total order, is the exact top-k. QED

Two preconditions make Theorem 2 about the real system, not only about real numbers:

  1. The rerank uses the same scoring function and the same f32 vectors as the oracle, so equality is against that oracle's floating-point score.
  2. Ties: tau is computed over E only. Computing it over a larger set (all tenants, all snapshots, or the unfiltered corpus) would make tau too high or too low and break the rule. This is a tested requirement for Stage E, not yet tested.

C.3 Why the deterministic gate prunes almost nothing (Derived, first order)

The interval width is W(x) = U_box - L_box = sum_i |q'_i| (u_i - l_i) = D_b * sum_i |q'_i| for interior cells. For roughly Gaussian q' coordinates E|q'_i| = sqrt(2/(pi P)), so sum |q'_i| ~ sqrt(2P/pi). With D_b = 2C/(sqrt(P) 2^b):

W  ~  2C * sqrt(2/pi) / 2^b            e.g. C = 3, b = 4:   W ~ 0.30
typical error std  sigma_b  =  D_b / sqrt(12)  ~  0.0068      (P = 256, b = 4)
ratio  W / (2 sigma_b)  ~  sqrt(6P/pi)  ~  22                  (P = 256)

The worst-case interval is an L1 quantity and the typical error an L2 one, so the gap grows like sqrt(P). A score gap between neighbours near the k-th rank is far smaller than 0.30, so almost nothing is pruned. This matches the measured behaviour (the deterministic gate reads about 3.7 to 4.0 bits). It predicts that no deterministic box bound can work at this dimension, and that a probabilistic per-vector bound is the only route to both a guarantee and pruning.

C.4 Probabilistic per-vector bound, RaBitQ style (Proposed)

RaBitQ (Theorem 3.2) gives an unbiased estimator and a bound of order 1/sqrt(D) with failure probability 2 exp(-c0 eps0^2), and uses it to decide what to re-rank. Prism's analogue, if the quantization errors e_i behave as independent and bounded over the randomness of the rotation seed:

P[ |s_hat - s| > t ]  <=  2 exp( -2 t^2 / D_b^2 )          (Hoeffding, sum q'_i^2 = 1, range D_b)
t_delta = D_b * sqrt( ln(2/delta) / 2 )

For P = 256, C = 3, b = 4, delta = 1e-3: D_b = 0.0234, t = 0.0457, about 6.8 times the first-order sigma_4. That is consistent in size with the measured tails (maximum error 5.2 to 7.1 sigma over 20 million pairs), which is encouraging but not a test.

Caveats, all open:

  • Independence of e_i is not proved for a three-round Hadamard rotation (correlated coordinates, section 4 of the loophole list). The probability is over the seed, per vector and per query, not simultaneously over all n vectors; a simultaneous guarantee costs a factor n in delta.
  • The estimate is biased toward zero without a residual stage (TurboQuant's 1-bit step, or RaBitQ's 1/<o_bar,o> correction); the bound above is for the error around the biased mean unless the bias is subtracted.
  • A probabilistic gate is a different contract: exact with probability >= 1 - delta per query, not always exact. It must be named that way in any result.

C.5 Floating-point, normalization, metrics, filters

Floating point (Proposed, not implemented). Bounds computed in f32 can be off by rounding. A sound implementation widens each bound: L_fp = L - eta, U_fp = U + eta, with eta covering (a) the summation error gamma_n sum |a_i|, gamma_n = n u / (1 - n u), u = 2^-24; (b) the error of the computed q' = fl(Rq) against Rq, at most ||delta_q|| added as eps_R; (c) the error of the stored x' and r; (d) the difference between the real score and the f32 oracle score used for the final order. Until eta is derived and a differential test passes, "certified" means certified in real arithmetic only.

Normalization. The derivation assumes unit x. For a stored norm n_x, scale L, U by n_x (positive). The zero vector has score 0 in the oracle, so L = U = 0. Unnormalized queries scale s_hat and t by ||q||.

Metrics (each needs its own statement; none is reused blindly).

  • Cosine on unit vectors: equals inner product; use C.1 to C.2.
  • Inner product on stored norms: multiply bounds by n_x.
  • Squared L2: ||q - x||^2 = ||q||^2 + n_x^2 - 2<q,x>. With exactly stored n_x, D_low = ||q||^2 + n_x^2 - 2U and D_high = ||q||^2 + n_x^2 - 2L. Discard c iff D_low(c) > tau_D, the k-th smallest D_high over E. Proved by the same argument with inequalities reversed. The Atlas engine ranks the negated square root, which is strictly monotone in the squared distance, so rank and ties are identical.

Filters. E is computed first (snapshot, tenant, predicate), then tau. If |E| < k, return all of E, ranked exactly. An empty E returns nothing and must not error.

C.6 What the exact rerank costs and stores

Exact rerank needs the original f32 vector, stored at 4d bytes per vector, plus the per-vector residual norms (one f32 for each of b = 1..4, so 16 bytes). Bytes fetched per query are n_S * 4d where n_S is the survivor count. These are included in the storage accounting on the algorithm page; the measured survivor counts and the I/O of a real tiered layout are Unmeasured.

C.7 What Stage C leaves unproved

  1. Floating-point margin eta (C.5).
  2. Independence of quantization errors under the structured rotation (C.4).
  3. A tight probabilistic bound for 4-plane codes; RaBitQ's bound is for 1-bit codes with an unbiased correction.
  4. Multi-stage union bound: each stage re-uses the same e_i at different resolutions, so failure events are dependent; the union bound is valid but loose.
  5. Behaviour on non-power-of-two d through zero padding.

2. Primary-source facts that matter

RaBitQ (read). Each unit data vector o becomes a D-bit code by a random rotation of a binary codebook. For a query q the estimator <o_bar,q> / <o_bar,o> is unbiased for <o,q> (Theorem 3.2, eq. 13), with a probabilistic bound (eq. 14):

P[ | <o_bar,q>/<o_bar,o>  -  <o,q> |  >  sqrt( (1 - <o_bar,o>^2) / <o_bar,o>^2 ) * eps0 / sqrt(D-1) ]  <=  2 exp(-c0 eps0^2)

where eps0 sets the failure probability and c0 is a constant. The authors state the bound as O(1/sqrt(D)) with high probability, and use it to decide which candidates to re-rank by exact distance. They report that PQ lacks such a bound and can fall below 60% recall even with re-ranking on some data.

Streaming quantization (read). Definition 2.1: a dynamic index is dynamically consistent if its answers after Build(X); Insert(y) equal those of Build(X ∪ {y}) (and likewise for delete), for each fixed random seed. Theorem 3.1 gives a dynamically consistent structure for the streaming (eps, delta)-ANN problem with memory O(n log N / eps^2 (log(1/(eps delta)) + log log N)) bits and one read and one write I/O per update, each of size O(eps^-2 log N) words, using full-precision points on disk. The practical method CoDEQ is data-dependent (median-based kd-tree partitions that stay stable under change), preceded by a standard data-oblivious random rotation. Baselines: FrozenPQ, RaBitQ, OnlinePQ.

TurboQuant (abstract). Random rotation makes coordinates near-independent, so an optimal scalar quantizer is applied per coordinate; a 1-bit Quantized JL step on the residual removes inner-product bias; distortion is within about 2.7 times the information-theoretic lower bound; data-oblivious.

HPC paper (abstract, corrected in P2). The abstract's stated result is about throughput: more cores can reduce query throughput by up to 30.67 percent, and 16 to 256 workers gives only 5.46 times. The abstract makes no P99 claim. Correction: the paper's body does report tail latency. Per the P2 fetch summary (not verified against the PDF), P99 rose by an average of 280.10 percent on Pes2o-VE and 344.77 percent on Yandex-T2I, with mean latency up 34.99 (Milvus), 102.74 (Qdrant) and 66.52 percent (Weaviate), on HPC systems (Aurora, Polaris, up to 256 workers on 64 nodes). These numbers are about scaling workers on a cluster, not about concurrent writes. They must not be attached to the OceanBase streaming study or to Prism's read-while-write jitter.

Snapshots (official docs). RocksDB ties a snapshot to a sequence number and makes compaction preserve what live snapshots see. SQLite readers fix a WAL end mark; a checkpoint must stop at it, long readers can stall checkpoints and let the WAL grow without bound. RCU guarantees data seen in a read-side section stays unreclaimed until a grace period ends.

5. Three lists

Already solved by prior work

  • Random rotation plus scalar quantization, data-oblivious (TurboQuant, RaBitQ).
  • An unbiased estimator with a probabilistic error bound that guides re-ranking (RaBitQ).
  • Dynamically consistent updates with bounded I/O, in theory and practice (2512.18335).
  • Real-time graph-index updates (FreshDiskANN).
  • Sequence-number snapshots and reclamation rules (RocksDB, SQLite, RCU).

Not solved by the designs reviewed (with the depth caveat above)

  • Progressive multi-bit reads from one stored code with a bound that is tight enough to prune at d = 256. Prism's measured provable bound prunes almost nothing; RaBitQ's form may fix this (Stage C, section C.3).
  • A measured read-while-write comparison of a data-oblivious code against a dynamically consistent data-dependent one, with tail latency over hours.

Potential Prism contribution, pending proof and measurement

  1. Nested planes as a storage layout that lets one copy serve several precisions. Unproven benefit; the only time measurement shows no gain over an optimised scan.
  2. A per-vector progressive bound in the RaBitQ style applied stage by stage. Not yet derived or tested.
  3. Snapshot semantics for a progressively read code. Not yet modelled.

If these three do not survive Stages E and F, the honest conclusion is that Prism is a re-implementation of known ideas with a measurement, which is still a publishable negative result.

Appendix E

Snapshot protocol

Prism: snapshot protocol (Stage C, 2026-10-27)

Status: Proposed. No model, prototype or crash test exists for this protocol. Research Note v1.0, not peer reviewed.

S.1 Why a log position is not a snapshot

A log sequence number (LSN) says how far the log has grown. A snapshot says which immutable index state a reader may use. They coincide only if the system defines and checks the relationship between durable records, applied records, published segments, deletions and reclamation. The reference systems keep that relationship explicit: RocksDB pins a snapshot to a sequence number and makes compaction preserve what live snapshots see; SQLite readers fix a WAL end mark and a checkpoint stops at it; RCU defers reclamation until pre-existing readers finish (official documentation, read in Stage B).

S.2 Objects

S.3 Legal transitions

Appended -> Durable -> Applied -> Sealed -> Published -> Retired -> Reclaimed
  1. Appended to Durable: the record reached the configured durability boundary. The write may be acknowledged. Not visible to readers.
  2. Durable to Applied: applied to the writer's state in LSN order. Visibility to the writer's own reads is a choice (read-your-writes); any lag must be stated, not implied.
  3. Applied to Sealed: the segment is complete and immutable; its codes and full-precision vectors are both present.
  4. Sealed to Published: one atomic pointer swap installs a new snapshot listing the segment. Only a fully sealed segment may be listed, so no reader sees a partial one.
  5. Published to Retired: compaction replaces segments with one holding the same visible records.
  6. Retired to Reclaimed: no live pin references the segment.

Illegal: publishing a segment that is not durable; reclaiming a segment a pin still references; a pin to an unpublished snapshot; a snapshot whose lsn_S exceeds D.

S.4 Visible set and invariants

V(S) = { r : lsn(r) <= lsn_S  and  not deleted at or before lsn_S }
IdInvariant
I1Repeatability: for one pin and one query the result is identical every time
I2No torn read: a commit is visible whole or not at all (codes and vector together)
I3Monotonic pins: successive pins by one reader never decrease lsn_S
I4Compaction transparency: compaction never changes V(S)
I5Durability bound: lsn_S <= D for every published snapshot
I6Tenant closure: the visible set of one tenant never contains another tenant's record
I7Eligible-set threshold: the pruning threshold tau is computed over the filter-passing subset of V(S) only

S.5 Recovery obligation

After a crash at any step, recovery must rebuild exactly the snapshots the durable log can justify, and discard any partially sealed segment. A snapshot whose segment list cannot be re-derived from the log must not be published. The index is derived data: it is never trusted over the log.

S.6 Reclamation and backpressure (undefined, open)

  • A pin that is never released blocks reclamation. SQLite documents the same failure: overlapping readers can stop checkpoints and let the WAL grow without bound. Prism needs a pin lease and an expiry rule, and a defined error when a reader outlives its lease.
  • Retained-version bytes need a cap with writer backpressure; the cap, the error and the test are not designed.
  • Delete semantics for a pinned reader (when a tombstone is reclaimable) are not specified beyond the formula in S.4.

S.7 Tests the protocol requires (none exist yet)

  1. A deterministic state-machine model with a crash injected at every transition, checking I1 to I7 after recovery.
  2. A history check (linearizability-style) over concurrent readers, writers and compaction.
  3. A long-lived pin test that fills the retention cap and observes backpressure.
  4. A differential test: results from a pinned snapshot equal an exact scan of V(S) for the same eligible set.

S.8 Relation to the Atlas engine

The production Atlas engine uses a simpler design: the write-ahead log is the single source of truth, the index is rebuilt from it on open, and a corrupt or poisoned state fails closed. It has no pinned readers or segments. This protocol is research, and no part of it changes the Atlas WAL contract or Gate 2 evidence.

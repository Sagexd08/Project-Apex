How the audit works

The aim is to find inputs where the algorithm looks right on easy data and breaks on plausible data. Every item below needs a reproduction input, the expected and actual behaviour, a severity, a root cause, a minimal fix and a regression test before it can be closed.

Most items are Open. This page lists work, not results. The few items marked with evidence say exactly what the evidence is.

Benchmark loopholes

  • Different hardware, threading, normalization, metric or recall definitions between competitors.
  • Training time or original-vector memory counted for one method and not another.
  • Average latency without tails; too few queries for a p99; cherry-picked seeds.
  • A synthetic simulation reported as a real-data benchmark.

All of these are guarded against by the protocol on the tournament page. None has yet been exercised against a second system.

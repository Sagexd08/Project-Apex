Manifesto

Why agents need a better-measured memory layer, what Prism is trying to show, and what would prove it wrong.

What we see

An agent does not work like a report. It reads what it knows, acts, writes what it learned, and reads again, often within a few milliseconds. The storage under most agents was designed for the opposite rhythm: load in bulk, build an index, then query for a long time. When the two meet, writes slow reads, tail latency spikes, and a memory that should be instant becomes the part of the loop everyone waits for.

We also see that moving bytes is expensive. A search over a million vectors is mostly a question of how many bytes the machine must pull through memory. A system that asks the question with fewer bytes may win on time and energy. We have not shown that it does; see the falsifiers below.

Status of this page

A statement of direction, not a result. Measurements live on the evidence page. Anything not measured there is Proposed.

What we believe

  1. Memory should be fast enough to disappear. An agent should consult everything it knows inside one thought, on a laptop, without a cluster.
  2. Nothing to train means no trained state to drift. A compressor learned from yesterday's data can be wrong about tomorrow's. A fixed random rotation has no opinion about the data. The error scale we gate on is measured, and rechecked on shifted data.
  3. Pay for precision only when the question needs it. Most of a corpus is clearly irrelevant to a given query, and one bit is enough to say so. Spend more bits only on the few vectors still in the running.
  4. A reader takes no lock and never sees half a write. Every read happens against a named point in the log. The same question at the same point gives the same answer. Readers still share CPU and memory with writers; the paper reports a cost.
  5. Say what was measured. Every number carries its data, its machine and the version of the code that produced it. A claim without a measurement is a goal.
  6. Keep it open. The reference implementation, the benchmark and the raw results are public, so anyone can disagree with us with evidence.

What we are building

A storage layout, Prism, where each vector is stored once as nested bit planes, searched by a cascade that reads more planes only for candidates still in contention, and served to readers through snapshots tied to the write-ahead log. It began as a question: could an agent memory be both fresh and fast, without a rebuild step between the two?

North star

A proposed goal, not a claim: an open-source vector database that agents can use as memory, built by one person with agents. We have no customers and no comparison with any other system. What we can do is write down the bar a reader would apply, and try to clear it in public.

Thesis and falsifiers

Thesis (Proposed). Nested bit planes plus log-pinned snapshots can improve the memory, recall and latency trade-off when a store is read while it is written. So far one synthetic benchmark shows bits read falling to about 1.06 per coordinate, and shows no established time saving over an optimised exact scan (inconclusive: the sign reversed between two runs).

The thesis fails if any of these turn out to be true:

  • The saving in bytes read does not become a saving in time on real hardware.
  • Real embeddings are far less friendly than our synthetic clusters.
  • The empirical gate misses neighbours more often than its tuning suggests, and a provable gate costs too much to be worth it.
  • An existing system, such as RaBitQ or TurboQuant combined with a segment design, already gives the same result.

We will publish the result either way. A negative result is an acceptable outcome. An unsupported positive claim is not.

Open by construction

Free has to mean both free of charge and free to inspect, modify and redistribute. The core database must not need a paid API, a hosted service, telemetry, or a language model to store, search and recover vectors.

CommitmentWhere it stands
LicenceThe Rust workspace manifests declare Apache-2.0. A top-level LICENSE file, a third-party notice inventory and a software bill of materials are Open.
Dependency policycargo-deny checks advisories, bans, licences and sources on every verification run. USearch is not adopted: its exact version and obligations are unaudited, so the exact-search index stays.
No mandatory paid serviceThe MVP server is standard-library Rust plus the engine. No API key from anyone else is needed to run the tests or the demo.
ReproductionSynthetic data with fixed seeds; raw results are committed. Large real datasets will be linked, not bundled, and licence-checked first.

Who it is for

A person running an agent on their own machine, with their own data, who should not need to rent a cluster to give that agent a memory. A small team that wants retrieval it can reason about and replay. A research community that deserves an open, reproducible reference for the read-while-writing case, not just for the static one.

The goal is modest in scope and large in reach: make good memory cheap enough to be everywhere.

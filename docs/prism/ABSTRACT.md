# Prism: abstract

Research draft, 2026-10-26. Numbers are from synthetic data on one machine (`benchmarks/prism/results/results.json`, source checksum `103fcb801fb94647`).

Agentic workloads read and write the same vector store within milliseconds of each other, and published measurements show tail latency inflating when inserts run during queries. We describe Prism, a storage layout for that case. Each vector is rotated by a seeded randomized Hadamard transform and stored once as four nested bit planes, so the quantizer has no trained state and cannot drift as the data changes. A query runs an error-gated cascade: it scores every vector with one bit and reads further planes only for candidates that can still reach the top k. Readers search immutable snapshots pinned to a write-ahead-log position, so a reader never waits for a writer and never sees a partial write. In a Rust reference implementation on synthetic data (20,000 vectors, 256 dimensions, 1,000 queries), a gate width of z = 3 returned the exact top 10 for every query while reading about 1.06 bits per coordinate per vector, against 4 for a flat 4-bit scan; at z = 2 recall@10 was 0.998. The saving in bits read did not become a saving in time: with a lookup-table kernel the cascade took 0.61 ms per query, against 0.55 ms for an optimised exact float scan. On harder synthetic sets it read 1.3 to 1.4 bits at z = 2, and over seven alternating trials a concurrent writer raised median P99 latency by 21% (range 12% to 34%). We state the open problems: a gate whose provable width does not cost most of the saving, real embedding data, and a kernel that beats an optimised exact scan.
